# Bioacoustics Cross-Species Rhythm Pipeline

This project contains a Python-based automated pipeline designed to extract timing, rhythm, and acoustic data from various audio recordings (human music, animal calls, etc.). It generates categorical rhythm raster plots to replicate the methodology of Roeske et al. (2020), as well as advanced statistical metrics (nPVI, CV, Entropy) and ratio histograms based on the methodology of Jadoul, Eleuteri, et al. (2025).

Key features of the current pipeline:

* **Desktop GUI application** — A full PyQt6 GUI (`GUI/pipeline_gui.py`) lets you configure all settings via widgets, run the pipeline, and preview plots — no code editing required. Desktop launchers are provided for macOS, Linux, and Windows.
* **Dedicated audio pre-processing** — `audio_editor.py` silences background noise while preserving the original timeline and duration. Processing order: ① High-Pass Filter → ② HPSS → ③ Spectral Denoising → ④ Amplitude Muting → ⑤ Crossfade.
* **HPSS (Harmonic-Percussive Source Separation)** — Optionally decompose audio into harmonic and percussive components before muting, isolating the rhythmic layer of interest.
* **Spectral denoising** — Suppress persistent tonal background sounds (cicadas, electrical hum, air conditioning) via spectral gating.
* **Six interchangeable onset detection methods** — `adaptive_hp`, `librosa`, `moving_median`, `superflux`, `cfar`, `per_band` — all housed in `onset_detectors.py`, feeding into a common two-stage architecture (coarse detection → Hilbert sample-level refinement).
* **Onset sharpness gate** — Reject onsets with weak attack slopes using the Hilbert envelope derivative, controllable via `ONSET_SHARPNESS_GATE` and `ONSET_SHARPNESS_WINDOW_MS`.
* **Onset clustering** — Onsets that occur within 25 ms of each other are merged before dyadic analysis, preventing near-simultaneous ensemble or chorusing events from being counted as separate beats.
* **Stable-rhythm export** — A filtered dyadic subset is exported alongside the full dataset, allowing the plotting scripts to generate both raw and filtered views from the same workbook.
* **Named presets** (`birdsong`, `percussion_clean`, `percussion_messy`, `primate`, `insect`) provide tuned onset-detection parameter defaults for common dataset types so researchers can switch contexts with a single variable.
* **Overall presets** — Save and load complete pipeline configurations (all 4 panels) as JSON files via the GUI or `preset_manager.py`. Includes an auto-generated `Preset_Default`.
* **Pipeline runner** — `main.py` runs all four stages in the correct order with clearly documented configuration flags.
* **Live plot preview** — The GUI's "Enable Plot Preview" window renders raster and histogram plots in real time as you adjust settings.
* **Chunked spectrograms** — Break long recordings into manageable time-windowed spectrogram images (`SPECTROGRAM_CHUNK_ENABLED`, `SPECTROGRAM_CHUNK_SECONDS`).

## Pipeline Steps in Detail

### Step 1: Audio Editor (`audio_editor.py`)
Pre-processes raw audio by silencing background noise while keeping the file's total duration and timeline intact. This is critical — cutting silence would distort inter-onset intervals in the downstream extraction step.

The muter also generates a "rejected noise" track for each file so you can manually audit what the algorithm removed.

**Command-line arguments:**

| Argument | Default | Description |
|---|---|---|
| `input_folder` (positional) | `audioFiles/` | Folder of raw audio files to process |
| `--db-threshold` | `30` | How far below peak volume (dB) is considered noise. Lower = more aggressive. Recommended: 20–25 (studio), 30 (general), 35–40 (noisy field) |
| `--highpass HZ` | `0` (off) | High-pass filter cutoff in Hz. Removes low-frequency rumble before muting. Recommended: 200 (general), 500 (birdsong), 80 (percussion) |
| `--fade-ms` | `5.0` | Crossfade duration (ms) at each mute boundary. Prevents hard transients from being falsely detected as onsets. Set to 0 to disable |
| `--auto-threshold` | off | Estimate a per-file noise floor and derive `top_db` dynamically instead of reusing one fixed threshold for every recording |
| `--noise-margin-db` | `6.0` | When auto-thresholding is enabled, sets the mute boundary this many dB above the estimated noise floor |
| `--save-noise-profile` | off | Save a `<filename>_noise_profile.json` file with the estimated noise floor, spectral profile, and chosen threshold |
| `--spectral-denoise` | off | Suppress persistent tonal background sounds (cicadas, hum, hiss) via spectral gating before amplitude muting |
| `--denoise-strength` | `1.5` | Spectral denoise aggressiveness. 1.0 = conservative, 1.5 = moderate, 2.0 = aggressive. Only used when `--spectral-denoise` is enabled |
| `--hpss` | off | Enable Harmonic-Percussive Source Separation. Decomposes audio into harmonic and percussive components |
| `--hpss-target` | `percussive` | Which HPSS component to keep: `harmonic`, `percussive`, or `both`. Only used when `--hpss` is enabled |
| `--hpss-margin` | `2.0` | HPSS separation softness (1.0 = hard mask, 4.0 = very soft). Only used when `--hpss` is enabled |

**Examples:**
```bash
# Default settings on the main audioFiles/ folder
python scripts/audio_editor.py

# Birds dataset with higher high-pass and more permissive threshold
python scripts/audio_editor.py audioFiles_birds --db-threshold 35 --highpass 500

# Chimpanzee recordings — keep low frequencies, tighter threshold
python scripts/audio_editor.py audioFiles_chimpanzee --db-threshold 25 --highpass 80

# Adaptive thresholding for mixed-quality field recordings
python scripts/audio_editor.py audioFiles --auto-threshold --noise-margin-db 6 --highpass 200 --save-noise-profile
```

**Processing order:**

The audio editor applies its filters in this fixed sequence:

1. **① High-Pass Filter** (`--highpass HZ`) — removes low-frequency rumble
2. **② HPSS** (`--hpss`) — decomposes into harmonic/percussive components
3. **③ Spectral Denoising** (`--spectral-denoise`) — suppresses persistent tonal noise
4. **④ Amplitude Muting** (`--db-threshold` / `--auto-threshold`) — silences everything below threshold
5. **⑤ Crossfade** (`--fade-ms`) — smooths mute/unmute boundaries

**Output folders** (created automatically alongside the input folder):
- `<input_folder>_muted_clean/` — cleaned audio for the onset finder
- `<input_folder>_rejected_noise/` — rejected noise tracks for auditing
- `<input_folder>_hpss_harmonic/` — harmonic component *(only when `--hpss` is used)*
- `<input_folder>_hpss_percussive/` — percussive component *(only when `--hpss` is used)*

**Important:** If you change the input folder, you must also update the `audio_folder` variable at the top of `onset_finder.py` to point to the corresponding `_muted_clean/` output folder.

### Step 2: Onset Finder (`onset_finder.py`)
Detects onsets in the pre-processed (muted) audio, computes interval-based rhythm metrics, and exports everything to a multi-sheet Excel workbook.

**Key configuration** (edited directly in the script's Section 1):
- `audio_folder` — must point to the `_muted_clean/` folder produced by the muter
- `ACTIVE_PRESET` — set to a preset name or `None` for manual tuning
- `ONSET_DELTA`, `MIN_INTER_ONSET_MS`, clustering and stable-rhythm toggles
- `ONSET_HOP_LENGTH` — controls temporal resolution of onset placement (default 256 ≈ 5.8 ms at 44.1 kHz). Lower values give finer precision but can introduce noise-triggered false onsets. Set to 512 to revert to the previous behaviour.
- `ONSET_BACKTRACK` — when `True`, onsets are rolled backward to the nearest energy minimum (can overshoot on noisy recordings). Default is `False` to keep onsets at the energy peak.
- `ONSET_REFINE_ENABLED` — when `True` (default), each coarse frame-level onset is refined to sample accuracy (~0.023 ms at 44.1 kHz) by finding the steepest energy rise in the Hilbert amplitude envelope within a ±`ONSET_REFINE_WINDOW_MS` search window. This achieves ≤1 ms timing precision while preserving the coarse detector's noise robustness.
- `ONSET_REFINE_WINDOW_MS` — half-width of the sample-level search window (default 10 ms). Increase if the coarse detector consistently lands far from the true attack.
- `ONSET_REFINE_ENERGY_GATE` — local energy ratio threshold (0.0–1.0). When > 0, onsets whose local envelope peak is below this fraction of the file's peak envelope are left at their coarse position to avoid snapping to noise. Set 0.0 to disable.

**Note on onset precision:** When refinement is enabled, Audacity labels use 6-decimal-place timestamps (prefixed `OnsetR_`) and the `Exact Onset Times Used (s)` column in the Excel summary is rounded to 6 decimal places. The `Onset Refinement` column in the File Summaries sheet records whether refinement was active and what window was used.

**Note on noise filters:** The extractor's built-in high-pass filter and amplitude gate are **disabled by default** because noise filtering is now handled by `audio_editor.py`. Re-enable them only if you are running the extractor directly on raw (un-muted) audio.

#### Onset Detection Methods (`onset_detectors.py`)

The pipeline supports **six interchangeable onset detection methods**, all housed in `scripts/onset_detectors.py`. Every method feeds into the same two-stage architecture:

1. **Stage 1 — Coarse detection:** One of the six methods below locates approximate onset positions (frame-level resolution, typically 1–12 ms grid).
2. **Stage 2 — Sample-level refinement:** The Hilbert-envelope derivative refiner (`refine_onsets_to_sample`) snaps each coarse onset to the exact sample with the steepest energy rise, achieving ~0.023 ms precision at 44.1 kHz.

> **Key insight:** The choice of coarse method affects *which* onsets are found (sensitivity, false-positive rate), **not** the final timing precision — that is always determined by the Hilbert refinement step.

Set `ONSET_METHOD` in the configuration section of `onset_finder.py` (or in a preset) to any of the names below.

##### Quick-Reference Table

| Method | `ONSET_METHOD` value | Resolution | Best for | Computational cost |
|---|---|---|---|---|
| Adaptive HP baseline | `"adaptive_hp"` | ~1 ms | Noisy field recordings, cicadas, Roeske 2020 replication | Medium |
| Librosa spectral flux | `"librosa"` | ~5.8 ms | Clean studio recordings, general-purpose | Low |
| Moving median | `"moving_median"` | ~1 ms | Slow/gradual onsets, whale song, sustained notes | Low |
| Spectral superflux | `"superflux"` | ~5.8 ms | Vibrato, trills, polyphonic signals | Medium |
| CFAR | `"cfar"` | ~1 ms | Radar-style detection, uniform-noise environments | Low |
| Per-band voting | `"per_band"` | ~1 ms | Broadband or multi-harmonic calls, dawn chorus | High |

##### Method Details and Parameters

**1. Adaptive HP Baseline** (`"adaptive_hp"`) — *Default*

Based on Roeske et al. (2020) / Sound Analysis Pro. Uses a Hodrick–Prescott filter to decompose the RMS energy envelope into a slowly varying trend and a residual. Onsets are where the residual exceeds the trend by more than a dynamic threshold. Excels at ignoring stationary noise (cicadas, wind, rain) because the HP trend absorbs it.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Smoothing λ | `HP_SMOOTH_LAMBDA` | `50` | Controls trend stiffness. Higher → smoother trend → more sensitive to transients. Range: 10–500 |
| Threshold λ | `HP_THRESHOLD_LAMBDA` | `5e7` | Scales HP filter output into a dynamic threshold. Higher → fewer onsets. Range: 1e6–1e9 |
| Envelope window | `HP_ENVELOPE_WINDOW_MS` | `10` | RMS window for the energy envelope (ms). Shorter → sharper but noisier |
| Envelope hop | `HP_ENVELOPE_HOP_MS` | `1` | Time step (ms) between envelope frames. 1 ms gives ~1 ms resolution |

**2. Librosa Spectral Flux** (`"librosa"`)

Standard spectral-flux onset detection via `librosa.onset.onset_detect`. Measures frame-to-frame increase in spectral energy. Fast and well-tested, but frame resolution is limited by `hop_length`.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Hop length | `ONSET_HOP_LENGTH` | `256` | STFT hop in samples. 256 ≈ 5.8 ms at 44.1 kHz. Lower = finer but noisier |
| Delta | `ONSET_DELTA` | `0.07` | Minimum spectral flux to trigger an onset. Higher → fewer false positives |
| Backtrack | `ONSET_BACKTRACK` | `False` | Roll onsets backward to nearest energy minimum. Useful for clean recordings; unreliable with noise |

**3. Moving Median** (`"moving_median"`)

Computes a Hilbert amplitude envelope, then subtracts a sliding-median baseline. Onsets fire where the envelope exceeds `threshold_scale × median`. Good for signals with gradual amplitude changes where spectral-flux methods tend to miss onsets.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Median window | `MEDIAN_WINDOW_MS` | `200` | Sliding window width (ms). Must be wider than the longest expected note/call |
| Threshold scale | `MEDIAN_THRESHOLD_SCALE` | `1.5` | Multiplier on the median baseline. Higher → fewer onsets |
| Envelope window | `HP_ENVELOPE_WINDOW_MS` | `10` | RMS window (ms) for the envelope. Shared with adaptive_hp |
| Envelope hop | `HP_ENVELOPE_HOP_MS` | `1` | Hop (ms) for the envelope. Shared with adaptive_hp |

**4. Spectral Superflux** (`"superflux"`)

Librosa's superflux algorithm: computes onset strength from a log-power Mel spectrogram with frequency-dependent lag, then applies local-maximum filtering. Designed to handle vibrato and trills better than simple spectral flux.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Hop length | `ONSET_HOP_LENGTH` | `256` | STFT hop in samples |
| Lag | `SUPERFLUX_LAG` | `2` | Number of frames for temporal comparison. Higher → ignores slow modulation |
| Max size | `SUPERFLUX_MAX_SIZE` | `3` | Frequency bins for local-max filtering. Higher → suppresses spectral ripple |
| Delta | `ONSET_DELTA` | `0.07` | Peak-picking threshold |

**5. CFAR (Constant False-Alarm Rate)** (`"cfar"`)

Borrowed from radar signal processing. Estimates a local noise floor from training cells on either side of a guard interval, then triggers an onset where the signal exceeds `threshold_factor × local_noise`. Works well when the noise floor is roughly uniform.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Guard window | `CFAR_GUARD_MS` | `20` | Guard interval (ms) on each side. Must be wider than the sharpest attack |
| Training window | `CFAR_TRAINING_MS` | `200` | Noise-estimation window (ms) on each side. Must be wider than the longest note |
| Threshold factor | `CFAR_THRESHOLD_FACTOR` | `4.0` | Multiplier on the estimated noise floor. Higher → fewer false alarms |

**6. Per-Band Voting** (`"per_band"`)

Splits the signal into frequency bands via a Mel filterbank, runs independent moving-median onset detection in each band, then requires a minimum number of bands to agree before declaring an onset. Good for broadband or multi-harmonic calls where energy onset timing varies across frequency.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Number of bands | `PER_BAND_N_BANDS` | `6` | How many Mel bands to use |
| Freq min | `PER_BAND_FREQ_MIN` | `200` | Lowest frequency (Hz) for the filterbank |
| Freq max | `PER_BAND_FREQ_MAX` | `None` (Nyquist) | Highest frequency (Hz). Set to cap high-frequency noise |
| Median window | `PER_BAND_MEDIAN_MS` | `200` | Per-band sliding median window (ms) |
| Threshold scale | `PER_BAND_THRESHOLD_SCALE` | `1.5` | Per-band threshold multiplier |
| Min bands | `PER_BAND_MIN_BANDS` | `2` | Minimum agreeing bands to confirm an onset |

##### Refinement Parameters (Stage 2)

These apply regardless of which coarse method is used:

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Enable refinement | `ONSET_REFINE_ENABLED` | `True` | Toggle Hilbert sample-level refinement on/off |
| Search window | `ONSET_REFINE_WINDOW_MS` | `10` | Half-width (ms) of the per-onset search neighbourhood |
| Energy gate | `ONSET_REFINE_ENERGY_GATE` | `0.0` | Below this fraction of peak envelope, onsets keep coarse timing (0 = disabled) |

##### Onset Sharpness Gate

Rejects onsets whose attack slope (measured via the Hilbert envelope derivative) is too weak.  This is useful for filtering out gradual amplitude changes that are not true percussive attacks.

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Sharpness gate | `ONSET_SHARPNESS_GATE` | `0.0` | Minimum normalised attack slope (0.0 = disabled). Higher values reject softer onsets |
| Sharpness window | `ONSET_SHARPNESS_WINDOW_MS` | `20` | Measurement window (ms) around each onset for computing attack slope |

The named presets include tuned sharpness gate values for their respective sound types.

##### Chunked Spectrograms

For long recordings, the full-file spectrogram can be very wide and hard to read. Enable chunking to split it into time-windowed segments:

| Parameter | Config variable | Default | Description |
|---|---|---|---|
| Enable chunking | `SPECTROGRAM_CHUNK_ENABLED` | `False` | When `True`, splits the spectrogram into equal-length segments |
| Chunk length | `SPECTROGRAM_CHUNK_SECONDS` | `30` | Duration of each spectrogram chunk in seconds |

##### Which Method Should I Use?

| Scenario | Recommended method | Why |
|---|---|---|
| **Noisy field recording** (cicadas, rain, wind) | `adaptive_hp` | HP trend absorbs stationary noise |
| **Clean studio / lab recording** | `librosa` | Fast, well-tested, stationary noise is absent |
| **Birdsong with trills or vibrato** | `superflux` | Spectral-lag comparison ignores frequency modulation |
| **Whale song / slow vocalizations** | `moving_median` | Catches gradual amplitude rises that spectral-flux misses |
| **Uniform-noise environment** (e.g. single-species chorus) | `cfar` | Radar-style detection optimised for flat noise floors |
| **Dawn chorus / multi-species overlap** | `per_band` | Cross-band voting rejects narrow-band interference |
| **Replicating Roeske et al. (2020)** | `adaptive_hp` | Closest to the Sound Analysis Pro algorithm described in the paper |
| **Not sure / first pass on new data** | `adaptive_hp` | Robust default; switch only if results look wrong |

## Installation Guide (From Scratch)
If you are setting this up on a new computer (Mac, Windows, or Linux) or handing this off to another researcher, follow these steps to build the environment from scratch.

### Step 1: Install Anaconda or Miniconda
* **Mac/Windows/Linux:** Download and install Miniconda from the official website: `https://docs.conda.io/en/latest/miniconda.html`

### Step 2: Create the Virtual Environment
Open the Terminal (Mac/Linux) or Anaconda Prompt (Windows) and run the following command to create an isolated environment using Python 3.11 (highly recommended for `librosa` compatibility):
`conda create -n rhythm_env python=3.11 -y`

### Step 3: Activate the Environment
`conda activate rhythm_env`

### Step 4: Install the Required Libraries
Use Conda to install the heavy math, audio, and statistical libraries:
`conda install -c conda-forge librosa pandas numpy matplotlib openpyxl scipy soundfile -y`

Then install the GUI framework via pip:
`pip install PyQt6`

Python 3.11 is still the recommended target environment for this project. This repository is intended to use the Conda environment named `rhythm_env`; do not create or activate a separate project-local `venv` with the same name, because that makes VS Code and terminal commands resolve to different Pythons.

**Note:** `soundfile` is required by `audio_editor.py` for writing `.wav` output files.

### Step 5: Update Script Paths
Open the `.py` files in the `scripts/` folder using a code editor. Update the configuration variables at the very top of each script to match the local computer's absolute folder paths (e.g., `audio_folder`, `output_excel_path`, `excel_path`).

For `audio_editor.py` you can also pass the input folder as a command-line argument instead of editing the script — see the examples in the **Step 1: Audio Editor** section above.

### Step 5.5: Choose a Preset (Optional)
`onset_finder.py` ships with named presets that apply tuned onset-detection parameters for common dataset types:

| Preset | Use Case |
|---|---|
| `birdsong` | Small passerines with rapid, high-frequency calls |
| `percussion_clean` | Clean percussion recordings — sensitive to quiet hits and rapid sequences |
| `percussion_messy` | Noisy percussion and drumming with sharp transients |
| `primate` | Primate calls and drumming — mid-frequency, moderate attack |
| `insect` | High-frequency percussive clicks (e.g. crickets, cicadas) |

To activate a preset, set `ACTIVE_PRESET = "birdsong"` (or another name) near the top of the script. To use fully manual parameters, leave it as `ACTIVE_PRESET = None`.

### Step 6: Understand the Workbook Outputs
Running `onset_finder.py` writes:

* `File Summaries`: one summary row per audio file, including noise-filter settings and the active preset name.
* `Dyadic Events (For Plots)`: the full dyadic dataset after optional onset clustering.
* `Dyadic Events (Stable Rhythms)`: the filtered dyadic subset used for cleaner rhythm visualizations when stable-rhythm export is enabled.

Both `flower_raster_plots.py` and `histogram_generator.py` generate separate outputs in `raw/` and `stable/` subfolders automatically when those sheets are present.

### Step 7: Noise-Handling Architecture
Noise filtering is **centralised in `audio_editor.py`** (Step 1 of the pipeline). This script handles, in order:

1. **High-pass filter** (`--highpass HZ`) — removes low-frequency environmental rumble (wind, traffic, etc.).
2. **HPSS** (`--hpss`) — Harmonic-Percussive Source Separation. Decomposes audio into harmonic and percussive components; you choose which to keep (`--hpss-target`). Useful for isolating drum hits from tonal backgrounds.
3. **Spectral denoising** (`--spectral-denoise`) — suppresses persistent tonal background sounds (cicadas, hum, air conditioning) via spectral gating. Strength is controlled by `--denoise-strength`.
4. **dB-based muting** — silences everything below a configurable threshold relative to the file's peak volume. Can be fixed (`--db-threshold`) or adaptive (`--auto-threshold`).
5. **Crossfade smoothing** (`--fade-ms`) — applies short fades at each mute/unmute boundary to prevent false onset detections.

The onset finder retains its own high-pass filter, amplitude gate, and **onset sharpness gate** as additional filtering layers. The sharpness gate (`ONSET_SHARPNESS_GATE`) rejects onsets with weak attack slopes using the Hilbert envelope derivative.

## GUI Application

The pipeline includes a full desktop GUI built with **PyQt6** (`GUI/pipeline_gui.py`). It provides:

- **4-panel interface** — one panel per pipeline step (Audio Editor, Onset Finder, Flower Raster Plots, Histogram Generator), each exposing all configurable settings as interactive widgets.
- **Smart conditional visibility** — settings that depend on other toggles are greyed out when irrelevant (e.g. HPSS margin is disabled unless HPSS is checked).
- **Inline descriptions** — three levels of detail (Off / Brief / Detailed) via a dropdown in the top bar.
- **Config Preview** — a live-updating JSON pane showing the effective configuration that will be passed to the pipeline.
- **Terminal Output** — streams stdout/stderr from the running pipeline in real time.
- **Enable Plot Preview** — opens a live preview window that renders raster plots and histograms as you adjust settings.
- **Overall Presets** — save, load, and delete complete pipeline configurations (all panels + run flags) as JSON files. An auto-generated `Preset_Default` captures the factory settings on first launch. Custom presets are named `Preset_Custom_1`, `Preset_Custom_2`, etc. (or any custom name). Presets are stored in `GUI/Presets/`.
- **Dark theme** — the GUI uses a dark colour scheme by default.
- **Desktop launchers** — platform-specific launchers in `GUI/` for macOS (`.app` bundle), Linux (`.desktop` file), and Windows (`.bat` + shortcut creator).

### Overall Presets

|---|---|
